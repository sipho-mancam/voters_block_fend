#### Voters Block API

Spring Boot REST backend for sports man-of-the-match voting.

## Running the API

From the `votersblock` directory:

```text
gradlew bootRun
```

The development configuration uses an in-memory H2 database. Data is reset when the application stops.

All request bodies use `Content-Type: application/json`. Successful responses are JSON. The API currently uses the `X-User-Role` header as a development authorization mechanism:

| Role | Capabilities |
| --- | --- |
| `ADMIN` | Create polls, add players, open or close voting |
| `VOTER` | View active polls and submit or update one vote per device per poll |
| `VIEWER` | View active polls and results |

## Endpoints

### Create a poll

```http
POST /api/admin/polls
X-User-Role: ADMIN
Content-Type: application/json
```

Request body:

```json
{
	"active": true
}
```

`active` is optional and defaults to `true`.

Response: `201 Created`

```json
{
	"id": 1,
	"active": true,
	"createdAt": "2026-09-20T08:30:00Z",
	"candidates": []
}
```

### Add a player to a poll

```http
POST /api/admin/polls/1/candidates
X-User-Role: ADMIN
Content-Type: application/json
```

Request body:

```json
{
	"name": "Alex Morgan",
	"metadata": "Forward"
}
```

Response: `201 Created`

```json
{
	"id": 10,
	"name": "Alex Morgan",
	"metadata": "Forward",
	"votes": 0
}
```

### List active polls

```http
GET /api/polls
X-User-Role: VIEWER
```

The role header defaults to `VIEWER` for this endpoint. `VOTER` and `ADMIN` are also allowed.

Response: `200 OK`

```json
[
	{
		"id": 1,
		"active": true,
		"createdAt": "2026-09-20T08:30:00Z",
		"candidates": [
			{
				"id": 10,
				"name": "Alex Morgan",
				"metadata": "Forward",
				"votes": 4
			}
		]
	}
]
```

### Upload multiple players

Players can be added in one request by sending a JSON array. The operation is atomic: if any player is invalid, no players from the request are added.

```http
POST /api/admin/polls/1/candidates/bulk
X-User-Role: ADMIN
Content-Type: application/json
```

Request body:

```json
[
	{
		"name": "Alex Morgan",
		"metadata": "Forward"
	},
	{
		"name": "Jordan Smith",
		"metadata": "Midfielder"
	}
]
```

Response: `201 Created`

```json
[
	{
		"id": 10,
		"name": "Alex Morgan",
		"metadata": "Forward",
		"votes": 0
	},
	{
		"id": 11,
		"name": "Jordan Smith",
		"metadata": "Midfielder",
		"votes": 0
	}
]
```

### Modify a player

```http
PUT /api/admin/polls/1/candidates/10
X-User-Role: ADMIN
Content-Type: application/json
```

Request body:

```json
{
	"name": "Alex Morgan Updated",
	"metadata": "Captain"
}
```

Response: `200 OK` with the updated candidate. The candidate ID and existing vote count are preserved.

### Remove a player

```http
DELETE /api/admin/polls/1/candidates/11
X-User-Role: ADMIN
```

Response: `204 No Content`. Any votes belonging to the removed player are also removed, so poll totals remain accurate.

### Cast a vote

```http
POST /api/polls/1/votes
X-User-Role: VOTER
Content-Type: application/json
```

Request body:

```json
{
	"candidateId": 10,
	"deviceId": "device-1"
}
```

The same `deviceId` represents one current vote in a poll. Submitting another vote with that device identifier replaces the previous vote. The device identifier should be supplied by the client application and remain stable for that device.

Response: `201 Created`

```json
{
	"pollId": 1,
	"candidateId": 10,
	"message": "Vote recorded or updated"
}
```

### Read poll results

```http
GET /api/polls/1/results
X-User-Role: VIEWER
```

`VOTER` and `ADMIN` are also allowed.

Response: `200 OK`

```json
{
	"pollId": 1,
	"active": true,
	"totalVotes": 4,
	"candidates": [
		{
			"id": 10,
			"name": "Alex Morgan",
			"metadata": "Forward",
			"votes": 4
		}
	]
}
```

### Open or close voting

```http
PATCH /api/admin/polls/1/active?active=false
X-User-Role: ADMIN
```

Response: `200 OK` with the updated poll object, including its candidates and current vote counts.

## Errors

Errors use this response shape:

```json
{
	"error": "Poll is closed"
}
```

| Status | Meaning |
| --- | --- |
| `400 Bad Request` | Required request data is missing or invalid |
| `403 Forbidden` | The role is missing, unknown, or not permitted for the endpoint |
| `404 Not Found` | The poll or candidate does not exist |
| `409 Conflict` | The poll is closed or the vote could not be updated |

Votes also have a database uniqueness constraint on `(poll_id, device_id)`, ensuring that each device has only one current vote per poll.
